02 · 설정값 반영

중간 density 값에 따라 실제 픽셀 배치가 달라집니다

왼쪽 3열 BEFORE와 오른쪽 3열 AFTER에서 같은 행·같은 값을 비교하세요. 각 칸 아래 숫자는 64픽셀 중 파랑의 개수입니다.

  • Floyd: 이전에는 .25/.5/.75가 같은 그림이었습니다. 이후에는 값이 커질수록 파랑이 늘어납니다.
  • Checker: 이전 .75는 전부 파랑이었지만, 이후에는 빨강16·파랑48입니다.
  • Dots: .25와 .75에서도 중간 단계가 생겼습니다. .5의 기존 점무늬는 그대로입니다.
  • Bayer: 전후가 같은 것이 정상입니다. 기존 동작의 회귀 확인용입니다.

어떤 경로와 스킬로 검사했나요?

이번 비교: 직접 회귀 검사112회

플러그인 wrapper/client → 이전 또는 현재 MCP → 실제 Aseprite 경로를 실행했습니다. 스킬을 자동 실행한 비교는 아닙니다. 이전 바이너리는 기준 커밋에서 추출해 당시 SHA-256과 대조했습니다.

저장된 native 파일26개를 PNG로 내보내 기존 픽셀 집계와 다시 비교했습니다. 원본 native 바이트는 보존됐습니다. 비교판은 원본8×8 이미지를 정수 배율로 확대했고, 팔레트 그림의 회색 체크만 투명 영역을 설명하기 위한 배경입니다.

분석용 low.png·rare.png는 두 버전에서 바이트가 같습니다. Native 제작은 같은 픽셀·인자·작업 순서로 실행했으며 native 파일 바이트가 같다고 주장하지 않습니다.
